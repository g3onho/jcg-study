# 2026-10-10 변경 인수 기록

## 동작
- 상단 메뉴, PC·태블릿의 학습/필기 2분할, 휴대폰의 세로 배치. 기존 문제별 `ink:<문제 ID>` 키와 코드 위 필기를 유지한다.
- 개념에서 들어간 문제는 같은 개념의 남은 문제를 추천한다. 한 묶음을 마치면 개념 복귀/다음 개념을 직접 선택한다. 일반 추천 규칙은 유지한다.
- 관리자는 원본 번들·출처·원본 PDF·문항 이미지를 받는다. 일반 사용자는 출처와 원문 이미지를 제외한 `content/student.json`만 받는다. 화면과 Storage 정책에서 모두 제한한다.
- 관리자가 설정에서 이메일·아이디·초기 비밀번호로 일반 계정을 등록한다. 공개 회원가입은 제공하지 않는다. 기존 이메일 로그인도 유지한다.
- 아이디 대응표는 서버 전용이며 로그인 함수는 이메일 조회 API를 제공하지 않는다. 계정 생성은 요청 토큰과 서버 관리자 역할을 검사한다.

## 적용 순서
1. 기존 Supabase SQL Editor에서 `supabase/schema.sql`을 실행한다. 기존 소유자의 관리자 역할/로그인 아이디 연결은 비공개 관리 절차로 처리한다. 이메일·개인 식별 정보는 공개 저장소에 기록하지 않는다.
2. `supabase/functions/account-access`를 배포한다. `verify_jwt=false`로 두고 함수 내부에서 계정 등록 JWT/관리자 권한을 검증한다. 로그인은 비밀번호 인증을 사용한다. Supabase 기본 서버 환경변수만 사용하고 비밀키를 프런트엔드에 넣지 않는다.
3. 현재 비공개 번들로 `node scripts/prepare-student.mjs <bundle.json> <student.json>`을 실행해 채점/코드/정답 보존을 확인하고 비공개 `private/content/student.json`에 올린다. 관리 화면의 사용자용 학습 파일 만들기도 같은 변환을 사용한다.
4. `main` 푸시로 GitHub Pages를 배포한다. 앱 저장소에는 학습 원문·학생용 번들·원본 PDF·개인 기록을 커밋하지 않는다.

- `npm run build`: 배포용 빌드 통과.
- 실제 비공개 콘텐츠: 문제 290개·개념 50개의 코드·정답·채점 기준 보존 확인. 콘텐츠 정답의 새 독립 검증을 뜻하지 않는다.
- 별도 로컬 PostgreSQL 호환 환경에서 관리자/학생/익명 파일 제한, 사용자 업로드·권한 상승 차단, 아이디 대응표 비공개, 로그인 횟수 제한, 개인 필기 격리와 스키마 재실행 후 기록 보존 확인.
- 예시 콘텐츠 브라우저 검사: 연결 문제 2개 완료와 다음 개념 선택, 코드/오른쪽 필기 저장 후 새로고침 복구, 휴대폰 390×844·태블릿 820×1180 배치, 학생의 자료 화면 직접 접근 차단 확인.
- 운영 서버: 스키마 실행 성공, 소유자 관리자/아이디 연결 조회, Storage 제한 정책 조회, 로그인 함수 배포 확인. HTTP로 미등록 아이디 401·익명 계정 생성 401·비로그인 원본 요청 실패 확인.

## 한계
- 원문 이미지에 출처가 포함되어 학생에게 제공하지 않는다. 학생 화면은 기존 텍스트·코드·표를 사용한다. 모든 290문항의 전사/레이아웃을 새로 대조하지 않았다.
- 실제 펜 기기, 다른 실물 기기 간 동기화와 실제 새 사용자 등록은 별도 확인이 필요하다.
- 서버 파일 업로드와 사이트 최종 배포/소유자 로그인 결과는 로컬 프로젝트 상태 기록에서 관리한다.

- 사용자 실기기 확인과 운영 서버 저장 조회 결과는 비공개 로컬 프로젝트 상태 기록에 남긴다.
